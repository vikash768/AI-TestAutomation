How to create a read-only GitHub token for a private repo
One repository (fine-grained, least privilege):
  1. GitHub → your avatar → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Resource owner: the account or org that owns the repo.
  3. Repository access → Only select repositories → pick the repo.
  4. Permissions → Repository permissions → Contents: Read-only (Metadata read is added automatically).
  5. Generate, copy the token (starts github_pat_), paste it in the token field above.
Multiple repositories (frontend + backend): same steps, but at Repository access → Only select repositories choose all the repos you entered above (the token must list every one). One token with all repos selected is enough; paste it once.
  • If the repos are under different owners/orgs, GitHub can't cover them with one fine-grained token — create one token per owner and run those repos as separate projects, or use a classic token with the repo scope (broader access).
  • For an organization repo, the org may require the token to be approved (Org → Settings → Third-party access → Personal access tokens).
Classic token (works across owners, broader): Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate → scope repo → if the org uses SSO, click Configure SSO → Authorize.

A public repo needs no token. The token is used only to clone, encrypted at rest, and wiped when the run finishes.

Every write the browser tries to make (POST, PUT, PATCH, DELETE) is intercepted and never reaches the server; only sign-in, token refresh and the logout test go through. Destructive actions only have their confirmation opened and cancelled. Credentials are encrypted at rest and wiped when the run finishes.
